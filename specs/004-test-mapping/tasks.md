**Organization**: Tasks grouped by user story (US1–US4 from spec.md), in priority order (US1 P1 → US2 P2 → US3 P2 → US4 P3). **US1 is the vertical slice**: per the spec's own framing ("The other three stories deepen the rows' breadth and truthfulness around this vertical slice"), US1 implements the method end-to-end with the minimal stage set its acceptance scenarios pin — the naming pairing strategy only (exact 90 / case-insensitive 70), `expect()`-chain assertion detection, and fallback-chain inference — so the `test_mapping` protocol surface, row shape, ordering, and determinism land as one deliverable. US2 extends `pairing.ts` with the direct-calls (80) and import-graph (75) strategies plus the full first-match-wins loop; US3 extends `assertions.ts` with `node:assert` detection and the full classification breadth; US4 extends `inference.ts` with the four provenance passes. US2 and US3 are file-disjoint (pairing.* vs assertions.*) and can proceed in parallel across implementers after US1 — their `tests/quality/pipeline.test.ts` extensions (T024 / T027) are the one shared touchpoint and must be sequenced or coordinated. US4's only true dependency is US1; it is scheduled last by priority. Cross-pipeline bookkeeping splits per the 003 precedent: the OpenSpec spec updates (FR-015) ride US1 — the story that flips the wire state, so no commit leaves the materialized specs contradicting the dispatch table — while README/AGENTS truthfulness rides Polish.

- The three pairing confidences are fixed integers — naming-exact `90`, naming-case-insensitive `70`, direct-calls `80`, import-graph `75`; deviations are bugs (FR-004). First-match-wins per test function: evaluation stops at the first strategy with any match; within the naming strategy the exact tier shadows the case-insensitive tier.
- The assertion-kind vocabulary is closed at four values plus the empty string: `equality`, `comparison`, `membership`, `error_check`, `""` — never `generic`, never `null` (FR-001/FR-008; the deliberate divergences from the reference analyzer's six-value set). Negation preserves the underlying kind; `.rejects.` routes to `error_check`; `.resolves.` preserves.
- The matcher table is normative data: `src/quality/matchers.ts` transcribes data-model Section 4 verbatim and `tests/quality/matchers.test.ts` diffs the module against the doc — implementation-time discretion cannot reshape it (FR-007, the routing-table anti-drift pattern).
- Inference is total: every row carries a canonical `side_effect_type` through the fallback chains even for effect-less targets (US1-7); the generator-aware chain (`ReturnValue` → first P0 → `GeneratorYield` → `AsyncGeneratorYield` → `ReturnValue`) is built in from the start — the reference analyzer's hardest-learned lesson (mismatched inference silently zeroed contract coverage for generator targets). The provenance passes only REORDER the return family ahead of the chain; they never bypass it.
- The parse-only degradation boundary (research R12): with no usable tsconfig, import-graph and direct-call resolution fall back to lexical name matching (barrels uncrossed — a documented imprecision), while assertion detection, the provenance passes, row shape, ordering, and confidences are unchanged — degradation reduces precision, never availability. Fixtures pin it (T023/T024; quickstart Section 7).
- Determinism is structural (research R10): every emitted collection is explicitly sorted before assembly (pairs by record order, rows by the FR-013 stable key), confidences and the matcher table are fixed data, and rows carry no free-text fields beyond the pinned values. The two-walk golden test re-runs the whole pipeline, not just the serializer.
